# SignSense

**Understand it before you sign it.**

SignSense is a Chrome extension that intercepts crypto wallet signing requests and explains them in plain English before you approve them. Explanations run privately on your device with Gemini Nano and fall back to Gemini in the cloud when the local model isn't available. Both paths are powered by the [Firebase AI Logic](https://firebase.google.com/docs/ai-logic) hybrid inference SDK.

## The problem

Wallet drainers rarely break into wallets. They trick people into signing. A "free mint" or "claim your airdrop" prompt can actually be:
- an unlimited token approval
- a gasless `Permit`
- an NFT listing priced at zero

Wallets display raw hex and long addresses that most people can't read, so users click **Confirm** without knowing what they agreed to.

## Features

| Feature | Description |
|---|---|
| **Local risk checks** | Deterministic decoding of `approve`, `setApprovalForAll`, EIP-2612 permits, Permit2, Seaport listings, Sign-In with Ethereum and `eth_sign`, with flags for known drainer patterns. No AI involved. |
| **Plain-English explanation** | A structured verdict, headline and checklist generated by Firebase AI Logic. A badge shows where it ran: **⚡ On-device (Gemini Nano)** or **☁ Cloud (Gemini)**. |
| **Community scam reports** | Users can report scam sites and addresses to Cloud Firestore. Matching reports show up as warnings for everyone who meets the same site or address. |
| **Deep check** | An optional cloud check, started by the user. It uses Grounding with Google Search to look for public scam reports about the site and contracts. |
| **Guarded approval** | High-risk requests require an explicit "I understand the risk" confirmation before **Continue** is enabled. |
| **Demo mode** | Built-in sample requests, so you can try every feature without a wallet. |

## How it works

### Request flow

```
 dapp page ──request()──► inject.js   (MAIN world: wraps window.ethereum + EIP-6963 providers)
                              │ postMessage
                              ▼
                         content.js ──chrome.storage──► review window (review.js)
                              ▲                              ├─ decoder.js     local risk rules
                              │                              ├─ ai.js          Firebase AI Logic (hybrid)
                              │                              └─ community.js   Firestore reports
                              │ decision (approve / reject)  │
                              └──────────────────────────────┘

 background.js opens the review window. Closing the window counts as Reject.
```

1. `inject.js` wraps the page's wallet provider and pauses any signing request.
2. The request is passed to the extension, and a review window opens.
3. The decoder classifies the request and sets a **minimum risk level**.
4. The AI explanation and the community lookup run in parallel.
5. The user chooses **Reject** or **Continue**. Only **Continue** forwards the request to the wallet.

### Safety model

- The deterministic decoder sets the **minimum** risk level.
- The AI and community reports can **raise** the risk level, but they can never lower it.
- Community reports on their own can only produce a warning. A request is marked high risk only when reports agree with a local risk check.

### Hybrid inference

| | On-device (Gemini Nano) | Cloud (Gemini) |
|---|---|---|
| **Used for** | The explanation for every request | Fallback when Nano is unavailable; the deep check |
| **Privacy** | Nothing leaves the device | Receives a redacted summary only (no wallet addresses or balances) |
| **Offline** | Yes | No |
| **Extra capability** | — | Grounding with Google Search |

Signing requests are among the most privacy-sensitive data a user has, because they link a wallet to a browsing session. For that reason SignSense runs on-device by default and uses the cloud only when it adds something.

### Firebase products used

| Product | Purpose | Code |
|---|---|---|
| **AI Logic** | Hybrid model (`InferenceMode.PREFER_ON_DEVICE`) with structured output (`responseSchema` / `responseConstraint`); cloud model with `googleSearch` for the deep check. | [`src/lib/ai.js`](src/lib/ai.js) |
| **App Check** | Protects the Gemini API and Firestore. MV3 extensions can't load reCAPTCHA, so a debug token is used. | [`src/lib/firebase.js`](src/lib/firebase.js) |
| **Remote Config** | Inference mode, model names, feature switches and report thresholds, changeable without a new build. | [`src/lib/firebase.js`](src/lib/firebase.js) |
| **Cloud Firestore** | Community reports at `reports/{target}/reporters/{uid}`, counted with `getCountFromServer`. | [`src/lib/community.js`](src/lib/community.js), [`firestore.rules`](firestore.rules) |
| **Authentication** | Anonymous sign-in, so each reporter counts once per target and can undo a report. Uses `firebase/auth/web-extension`. | [`src/lib/community.js`](src/lib/community.js) |

## Getting started

### Prerequisites

- **Google Chrome 139 or later** (desktop)
- **Node.js 18 or later** and npm
- A **Google account**, for the Firebase console

Setup takes about 15 minutes.

### Step 1: Clone and install

```bash
git clone https://github.com/Christopherdominic/signsense.git
cd signsense
npm install
```

### Step 2: Create a Firebase project

1. Open the [Firebase console](https://console.firebase.google.com) and click **Create a project**.
2. In the project, go to **Project settings → General → Your apps** and click the **Web** icon (`</>`). Register the app; you don't need Firebase Hosting.
3. Keep the `firebaseConfig` object it shows you. You'll need it in Step 6.

### Step 3: Enable Firebase AI Logic

1. Go to **AI Services → AI Logic** and click **Get started**.
2. Choose the **Gemini Developer API**. It has a free tier.

### Step 4: Set up App Check

1. Go to **App Check → Apps** and select your web app.
2. Register any provider. reCAPTCHA Enterprise is fine; the extension doesn't actually use it, but a provider is required before you can create debug tokens.
3. Open the app's menu (**⋮**), choose **Manage debug tokens → Add debug token**, and copy the token.

> **Keep this token private.** Anyone who has it can use your project's Gemini quota.

### Step 5: Set up Firestore and Authentication

These are needed for community reports. If you skip them, the rest of the extension still works.

1. **Create the database.**
   1. Go to **Build → Firestore Database → Create database**.
   2. Choose **Production mode** and any location.
2. **Publish the security rules.**
   1. Open the **Rules** tab.
   2. Replace the contents with [`firestore.rules`](firestore.rules) and click **Publish**.
   3. With the Firebase CLI, you can run this instead:
      ```bash
      firebase deploy --only firestore:rules
      ```
3. **Enable anonymous sign-in.** Go to **Build → Authentication → Get started → Sign-in method → Add new provider → Anonymous**, turn on **Enable**, and click **Save**.

### Step 6: Configure the extension

```bash
cp src/config.example.js src/config.js
```

Open `src/config.js` and fill in:
- `firebaseConfig`, using the values from Step 2
- `appCheckDebugToken`, using the token from Step 4

`src/config.js` is listed in `.gitignore` and must never be committed.

### Step 7: Build

```bash
npm run build
```

The unpacked extension is written to `dist/`.

### Step 8: Load it in Chrome

1. Open `chrome://extensions`.
2. Turn on **Developer mode** (top right).
3. Click **Load unpacked** and select the `dist/` folder.
4. Pin SignSense to the toolbar.

### Step 9 (optional): Enable on-device inference

1. Open `chrome://flags/#prompt-api-for-gemini-nano-multimodal-input`, set it to **Enabled**, and restart Chrome.
2. Open the SignSense popup and click **Download Gemini Nano**.

Until Gemini Nano is downloaded, explanations come from the cloud (☁).

### Step 10 (optional): Enforce App Check

Do this after you've confirmed everything works.

1. Go to **App Check → APIs**.
2. For **Cloud Firestore**, check that requests show as **Verified**, then click **Enforce**.
3. Repeat for **Authentication**.

Enforcement can take up to 15 minutes to take effect.

### Verify the installation

1. Open the SignSense popup and click the **Unlimited USDC approval** demo.
2. A review window should open with all of these:
   - a **High risk** verdict
   - decoded details of the request
   - an AI explanation with a ⚡ or ☁ badge
   - a **Community reports** card

## Usage

### Demo mode (no wallet required)

Open the SignSense popup and choose one of these demo requests:

| Demo | What it shows |
|---|---|
| Unlimited USDC approval | An `approve` call that lets an unknown spender take all of a token |
| NFT `setApprovalForAll` | Control of an entire NFT collection |
| Gasless permit | An EIP-2612 signature that works like an approval |
| Zero-price listing | A Seaport order that gives an NFT away |
| Phishing sign-in | A Sign-In with Ethereum message from a mismatched domain |
| `eth_sign` | A blind signature over a raw hash |
| Normal transfer | A low-risk baseline |

### With a real wallet

1. Install MetaMask, or any wallet that supports EIP-1193 or EIP-6963.
2. Switch to a **testnet**.
3. Use any dapp as normal. When it asks you to sign, SignSense opens **before** your wallet does.
   - **Reject** cancels the request.
   - **Continue** passes it on to your wallet as usual.

### AI modes

Choose one in the popup:

| Mode | Behavior |
|---|---|
| **Balanced** (default) | Uses Gemini Nano when available, otherwise falls back to the cloud. |
| **Strict privacy** | Uses on-device only. Nothing is sent to the cloud. |
| **Cloud only** | Always uses cloud Gemini. |

To see the hybrid switch in action:
1. Download Gemini Nano.
2. Open a demo. The badge shows ⚡.
3. Turn off your network and open the demo again. The explanation still works.
4. Switch to **Cloud only** to compare.

### Reporting a scam

In the **Community reports** card:
1. Choose a reason.
2. Click **Report as scam**.

Your report covers the site and the counterparty address. Well-known tokens and protocols can't be reported. You can withdraw a report at any time with **Undo my report**.

| Reports | Local checks | Result |
|---|---|---|
| 1 or more | Any | ⚠️ Warning |
| 3 or more | Found a risk | ⛔ High risk |
| 3 or more | Found no risk | ⚠️ Warning (reports alone never escalate) |

## Configuration

All runtime settings are read from **Remote Config**. If a parameter isn't set, the default from [`src/lib/firebase.js`](src/lib/firebase.js) is used. To override one, add a parameter with the same name in **Remote Config** in the Firebase console.

| Parameter | Type | Default | Description |
|---|---|---|---|
| `quick_mode` | string | `prefer_on_device` | Default inference mode: `prefer_on_device`, `only_on_device`, `only_in_cloud` or `prefer_in_cloud` |
| `quick_cloud_model` | string | `gemini-3.5-flash-lite` | Cloud model for explanations. Also the fallback for the deep check. |
| `deep_cloud_model` | string | `gemini-3.8-flash` | Cloud model for the deep check |
| `deep_check_enabled` | boolean | `true` | Shows or hides the deep check |
| `community_reports_enabled` | boolean | `true` | Shows or hides community reports |
| `community_warn_at` | number | `1` | Reports needed for a warning |
| `community_danger_at` | number | `3` | Reports needed for high risk, if a local check agrees |

Remote Config values are cached for one hour.

### Testing

```bash
npm test
```

The test suite covers:
- the decoder's risk rules for every supported request type
- **privacy:** no data sent to a model contains a full wallet address, and the deep-check context never includes the user's own address
- the community-report rules:
  - well-known contracts can't be reported
  - target IDs match the Firestore rules
  - reports alone never reach high risk

## Troubleshooting

| Symptom | Likely cause and fix |
|---|---|
| `npm run build` prints *Missing src/config.js* | Complete [Step 6](#step-6-configure-the-extension). |
| Explanation fails with an App Check error | `appCheckDebugToken` is missing or wrong. Check it under **App Check → Manage debug tokens**, then rebuild. |
| `429` / *quota exceeded* | You've reached the Gemini free-tier limit. Wait and retry, set a lighter `deep_cloud_model` in Remote Config, or upgrade the project to the Blaze plan. The deep check already retries with `quick_cloud_model` automatically. |
| Badge is always ☁, never ⚡ | Gemini Nano isn't available. Follow [Step 9](#step-9-optional-enable-on-device-inference), and check that your device meets Chrome's hardware requirements. |
| *Community reports are unavailable* | The Firestore database doesn't exist, you're offline, or App Check enforcement is rejecting the token. See [Step 5](#step-5-set-up-firestore-and-authentication). |
| Reporting fails with `permission-denied` | The security rules aren't published, or anonymous sign-in isn't enabled. |
| SignSense doesn't open for a dapp | The wallet may freeze its provider object. Demo mode still works. |

For detailed errors, right-click the review window, choose **Inspect**, and open the **Console** tab.

## Privacy and security

- **On-device first.** In the default mode, nothing leaves the device when Gemini Nano is available.
- **Redacted cloud prompts.** Cloud requests contain a summary with shortened addresses. They never contain the user's own address or balances.
- **Minimal community data.** Firestore stores only the reported site or counterparty address, the reason and a timestamp. It never stores the reporter's wallet.
- **Locked-down database.** The security rules allow users to write only their own report documents, validate every field, and deny all other access.
- **No remote code.** The Firebase SDK is bundled at build time, as Manifest V3 requires.

## Limitations and roadmap

**Current limitations**
- Only the outer call of batched transactions (`multicall`, Universal Router) is decoded.
- Token and protocol allow-lists are small and built in.
- Wallets that freeze their provider object can't be intercepted.
- Anonymous accounts can be recreated, so report counts can be inflated. Two defenses limit this:
  - Reports alone never escalate to high risk.
  - App Check enforcement blocks requests that bypass the extension. Because the debug token ships with the extension, this is a deterrent rather than a guarantee.

**Planned**
- Decode the inner calls of batched transactions.
- Require Google sign-in to **file** reports, so each Google account gets one vote.
- Move report writes to a Cloud Function that:
  - rate-limits by user and IP
  - ignores brand-new accounts
  - weights reporters by reputation
  - lets reports expire
- Expand the built-in protocol lists.
